# FEAT-164 retained Runtime qualification

Contract impact: none. The three explicitly invoked FEAT-164 integration fixtures keep their request/response behavior, assertions, exact binary checks, bounded loopback endpoints and normal EOF shutdown. Only test directory placement and successful cleanup change: complete Runtime homes are retained under `YIJIE_FEAT164_RETAIN_ROOT` (or the normal temporary parent when unset). There is no production code, public wire, schema, Runtime core or patch change.

`python3 scripts/feat164-retained-runtime-conformance.py --output NEW_DIRECTORY --go-binary GO --runtime-binary R5 --runtime-manifest R5_MANIFEST --legacy-binary OLD --legacy-manifest OLD_MANIFEST` runs the reviewed r5 and historical artifacts. It records exact source hashes, 12 expected cases/zero skips, 38 bounded loopback HTTP and ten retained homes. It stops at the first failed group without retries or process signals. Provider credentials and endpoint overrides are not inherited. The historical producer's seven local K3 calls occur before each scenario's explicit cutoff; no post-cutoff K3 call is allowed.

After successful normal shutdown, it requires no open handles, copies every file including any WAL/SHM, and checks all four SQLite databases in read-only copies. It never runs checkpoint, deletes WAL or removes the original homes. A nonzero WAL or incomplete normal stop is a failure to investigate, not permission to clean files manually.

The unchanged scenarios cover text/image/file input, title, input-only draft/resume, expert instruction routing, ordinary local read/continuation, inherited native child identity, explicit and automatic compaction, Guardian review of an explicitly requested ordinary local copy, historical parent/child cutover, retired loaded identity rejection and native child terminal/cold-history behavior. They are not adversarial tests; no executable substitution, permission corruption, forced termination or attack payload is used. Ordinary compatibility metadata samples qualify a guard, not a change to the product catalog.

This is scoped protocol/lifecycle evidence, not a production release, supplier G2V, full TCONF04, GUI acceptance or authority to migrate daily data. The already-built App retains its existing Host source pin; a test-only commit is separately linked by proof that all product files match that pin. Do not rebuild App binaries merely to refresh a test-source pin.
