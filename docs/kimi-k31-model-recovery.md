# FEAT-164 S2 Host model recovery foundation

Contract impact: semantic; the complete feature remains breaking. This consumes the existing `chat-models-v2` 0.2.0 source at Contracts `f2819c66a2368aaff37216a46c48d5cd81df1747`. No public DTO or Runtime protocol is added. Only the explicit local Kimi candidate selects the new Store writer. The current running App and daily data are not migrated by this source change.

The candidate registers source-defined selection, read-only operation receipt, and explicit recovery routes under `/v2/model-chat`. A repeated selection POST never automatically reapplies an unfinished operation. Recovery must name the original v2 operation, target, revision, session and thread, and must recheck idle state, cleanup, pending turns, Runtime approvals, pending titles and market/expert work. Ordinary sessions only are eligible in this foundation; draft/market activation remains fenced. Native selection/recovery remains disabled until its own durable operation-version migration is ready.

Private Store schema 11 wraps the previous domain schema 7/8/9/10 in `model_v2_base_schema`; existing domain buckets and v1 operation bytes are preserved. `model_operations_v2` stores version 2 intents with original profile, thread, request and stages `prepared`, `apply_dispatched`, `receipt_validated`, `committed`, `uncertain`. A validated receipt contains the exact thread/model/provider/effort. Selection and committed operation are written in one transaction after receipt validation. Normal reopen preserves the schema; older binaries reject 11. Rollback requires this compatible reader with execution paused; never lower metadata or copy a current database into an old binary.

Only a matching committed operation replays its original result without readiness or Runtime calls; callers then separately read the current selection. The read-only v2 receipt adapter preserves v1 result schema and fields without adding availability. An unfinished v1 record has no trustworthy dispatch/thread proof, stays unknown and cannot be taken over by a new target. Candidate v1 selection writes are fenced. Title generation shares the candidate model-operation lock so new auxiliary work cannot cross a switch.

Tests use ordinary temporary databases and state fixtures, normal Runtime/Store shutdown and a local HTTP response. No executable replacement, forced kill, permission sabotage or live provider is required. `TestFEAT164V2NativeOperationLifecycle` uses the exact pinned Runtime paths supplied by the normal integration variables, verifies one local MiniMax response, same-thread Kimi selection, normal Runtime/Store reopen, read-only terminal replay and a new MiniMax selection. It is not a Desktop platform acceptance test.

Remaining S2 work: versioned Native selection intent and explicit recovery UX, never-sent dispatch evidence and domain cancellation for ordinary/market/expert work, actual App historical migration and platform verification. Old queued/zero-attempt state is insufficient: existing ordinary retry can reset attempt counts. No cancellation, plan rewrite or automatic release is implemented here.
